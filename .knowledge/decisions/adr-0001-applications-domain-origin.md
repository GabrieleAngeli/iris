## Context

Before building Applications/Deployments/Actions, two sibling folders outside
this repository were reviewed: `F:\Work\Iris_v2` (an incomplete draft from AI
prompt scaffolding, never committed to git, backend never compiled) and
`F:\Work\Iris_v3` "Momentum" (a mature, unrelated IoT product — the folder name
is coincidental, confirmed by searching its code/history for "Iris" and
finding nothing).

## Decision

- Reuse **Iris_v2's domain shape and validation rules as a concept map only**:
  `ServerNode`, `ApplicationDefinition`/`Version`, `PlaceholderDefinition`,
  `DeploymentAssociation`, `DeploymentCheck`, `PreparedAction`, and the
  deployability checks (unresolved placeholder, unbound dependency,
  incompatible OS, missing capability, port collision, insufficient capacity).
  Do not port the code as-is (in-memory persistence, no current EF/CQRS/GUIDv7
  conventions).
- Reuse from Iris_v3 "Momentum" **only two operational patterns, not any
  domain code**: the `.contex/` context-pack convention (adopted, see
  `.contex/README.md`) and the Gitleaks+Semgrep security scanning
  configuration (`.github/workflows/security.yml` — deliberately *not* the
  full Momentum pipeline, since Checkov/tfsec have no IaC to scan in this
  repo).
- Applications was then built **backend-first**, directly on current
  conventions (see `.contex/01-decisions.md` "Layering"), without a client
  page in its first increment.

## Alternatives considered

Porting Iris_v2's code directly was rejected: it never compiled successfully,
used in-memory repositories, and modelled `Customer`/`ServerNode` as its own
records instead of referencing the tenancy/infrastructure model this repo
already has.

## Consequences

- `Deployments` (not yet modelled in `.knowledge/`, see `.contex/02-operational-plan.md`)
  must reference `ApplicationDefinition`/`ApplicationVersion`,
  `Customer`/`CustomerContext` and `ServerNode` with real foreign keys — never
  re-introduce Iris_v2's duplicate record types.
- The Validation Engine's rule set (placeholder/dependency/OS/capability/port/
  capacity checks) is a direct, deliberate carry-over from Iris_v2's concept
  map — if it ever needs to diverge from that shape, treat it as a decision
  worth its own ADR, not a silent code change.

## Status

Accepted and largely implemented — see `.contex/00-current-state.md` for what
of this decision is actually built today (Applications catalog: done;
Deployments/Validation: partially done, out of scope for this `.knowledge/`
PoC pass).
